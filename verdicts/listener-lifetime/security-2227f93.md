## Findings
- [medium] signal_cc/entry/hooks.py:57 blocks: yes. Failure: if the owner types or pastes a prompt at the Mac that only mentions the wake text (e.g. `rename WOKEN = "The owner replied from Signal, away from the Mac (signal-plugin-cc):" to WAKE`, a likely prompt in this repo's own sessions), `WOKEN in prompt` treats it as self-started and quiet() returns early. The listener keeps running with leave_on_return=False for up to cfg.listen (3600 s), and the thread is not forgotten, so a Signal reply quoting any of the session's messages wakes a session the owner is now driving. On main the same prompt stops the listener (SIGTERM). This breaks acceptance 3 ("a prompt typed at the Mac ... the listener stops ... as today") and the gate's check that a prompt merely containing the wrapper text counts as typed (CWE-807, reliance on untrusted input for a security decision). Fix: `prompt.lstrip().startswith((REPORT, WOKEN))`. The real wake opens with `<task-notification>` (local transcripts: `<task-notification>...Stop hook feedback</summary></task-notification><system-reminder>Stop hook blocking error ...: The owner replied ...`), and the bare-wake test opens with WOKEN, so both still count.
- [low] signal_cc/domain/routing.py:36 blocks: no. If a reply starts with a 4-hex-character word ("feed the cat", "cafe later") that matches any kept tag of any session, it is routed by that tag even when it quotes another session's message. Live tags already took precedence over quotes, so the rule is not new, but the PR widens the tag set from a few live tags to every kept tag of the last day. Consider letting a quote win over a kept (not live) tag.
- [low] signal_cc/domain/routing.py:42 blocks: no. Untested: moving the `mine` check above the live-tag check survives the suite. No test pins that live tags win over `mine`.

A session that keeps continuing from Signal keeps tags older than a day, and only its own session can take them.
