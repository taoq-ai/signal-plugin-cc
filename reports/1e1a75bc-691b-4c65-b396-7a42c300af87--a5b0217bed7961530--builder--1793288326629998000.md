**What changed**
- **Port and adapter:** a new `Journal` port in `signal_cc/ports.py`, with a `FileJournal` adapter in `signal_cc/adapters/files.py`. Only `wiring.py` builds it, through `wiring.journal(cfg)`. The adapter adds a UTC time to each JSON line it appends to `<home>/relay.log`. If the write fails, it prints to stderr and never raises.
- **One line per prompt:** `Conversation.ask` writes exactly one line however the prompt ends, with kind, tag, session, outcome and seconds waited. Each outcome is set before the closing message goes out, so a failed send there still logs the real outcome. Prompts that stay at the Mac get no line.
- **Kind and session:** each form now has a `kind` field (permission, question or continue). `wiring.conversation(cfg, session)` takes the hook's session id.
- **Handler failures:** both error branches in `entry/cli.py` log the handler and the exception type. The exception message is never logged, because it can quote the prompt.
- **Docs:** a "Relay log" section in the README, the Architecture table updated, and `.github/ISSUE_TEMPLATE/relay-failure.md`, which applies the label and asks for the log lines. The `relay-failure` label already exists (D93F0B), so I didn't create it.

**Choices I made (recorded in the PR body under Assumptions)**
- `kind` lives in `signal_cc/domain/forms.py`, which is outside the item's file list.
- A failure before the first message is sent (subscribing, claiming a tag, or the first send) logs `send failed`.
- When `ask` raises, the log gets two lines: one from `ask` with the tag, one from `cli.py` with the handler.
- No lock on appends: each line is a single append-mode write.
