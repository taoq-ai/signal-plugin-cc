**What the probe found** (recorded with `wuwei plan run plan-approval --reason`)
- **Where it ran:** Claude Code 2.1.311, interactive sessions in `screen`, throwaway hooks in `/private/tmp/claude-501/-Users-leone-taoq-ai-github-ziran-paper/1e1a75bc-691b-4c65-b396-7a42c300af87/scratchpad/plan-approval-probe`. `claude -p` never offers ExitPlanMode, so a headless run can't test it.
- **What the hook gets:** ExitPlanMode's `tool_input` has two fields, `plan` (markdown) and `planFilePath` (`~/.claude/plans/<slug>.md`). A PermissionRequest fires after PreToolUse, with `permission_mode: plan`.
- **A bare allow does nothing:** `{"behavior":"allow"}` is ignored, with or without `setMode`, and the plan dialog stays up. A PreToolUse `permissionDecision: allow` is ignored too.
- **Approve with edits still asked:** an allow that includes `updatedInput` equal to the tool_input leaves plan mode. The mode becomes `default`, and the next Write raises its own PermissionRequest.
- **Approve with edits accepted:** adding `updatedPermissions: [{type: setMode, mode: acceptEdits, destination: session}]` switches to `acceptEdits`. Write and Edit then ran without asking.
- **Keep planning:** a deny with a message keeps plan mode, and Claude reads the message as feedback.

So the relay can approve a plan safely, as long as every approval returns `updatedInput`.
