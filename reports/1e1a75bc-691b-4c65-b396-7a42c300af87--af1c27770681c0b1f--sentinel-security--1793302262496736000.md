**Security gate for listener-lifetime (PR #14, head 2227f93): FIX.** One finding blocks. The rest are notes.

**What blocks:**
- **The wake text check is too wide.** `self_started()` (`signal_cc/entry/hooks.py:57`) treats any prompt that contains the wake text anywhere as one Claude Code started itself.
- **When it bites:** a prompt the owner types or pastes at the Mac that only mentions the text, e.g. `rename WOKEN = "The owner replied from Signal, away from the Mac (signal-plugin-cc):" to WAKE`. In this repository's own sessions that is a likely prompt.
- **Effect:** `quiet()` returns early, and the listener keeps running for up to 3600 s after the owner is back. The session also keeps its earlier messages, so a Signal reply quoting any of them wakes a session the owner is now driving.
- **Proof:** I ran the same `quiet()` test against main and head with a real child listener. Main stops the listener with SIGTERM; head sends no signal. This breaks acceptance 3 and the check you named.
- **Fix:** one line, `prompt.lstrip().startswith((REPORT, WOKEN))`. The real wake prompt starts with `<task-notification>`, which I confirmed in the local transcripts, and the bare-wake test starts with the wake text, so both still count as self-started. The full suite passes with this change. With it, the same prompt sends SIGUSR1, clears the listener and turns away off.

**What holds:**
- **No cross-session wake.** I fuzzed 2.4M replies across live, kept and expired tags, quotes, reactions, poll votes, tag spellings and words that look like tags. No reply woke a session that was neither the owner of the quoted message nor of the tag. No reply was taken by two listeners.
- **Prompt spellings:** upper case, the wrapper mid-text and a leading BOM count as typed, which fails safe. Leading whitespace and a leading non-breaking space count as self-started.
- **threads/ files** follow `private.py`'s rules: folder 0700, file 0600, each line only `tag timestamp` with no message text. Writes never follow a symlink, and the session id is checked before use.
- **A file untouched for a day** is dropped by the next claim, before any listener reads it.
- **Tests:** the full suite passed (102 tests) in a git-archive copy with a temporary home and an ephemeral stub port. Nothing touched Signal, port 8299 or `~/.config/signal-plugin-cc`.
- **Mutants:** 15 of 16 changed guards, reversed one at a time, are caught by the suite.

**Notes that don't block:**
- **Tag beats quote, over more tags.** A reply starting with a four-letter hex word such as "feed" or "cafe" that matches any kept tag goes by that tag, even when it quotes another session's message. That rule is older than this PR, but the set of matching tags is now every kept tag from the last day, not just the few live ones.
- **One untested ordering.** Checking a session's own kept tags before live tags is a mutant the tests don't catch. The head's order is correct.
- **Expiry is per session.** A tag older than a day stays while its session keeps getting new messages, as the README describes. Only its own session can take it.
- **Reads follow symlinks.** Reads under `threads/` follow a planted symlink, the same as the existing `pending/` reads; writes never do.
- **One timing test can fail under CPU load.** `test_listen_in_a_headless_run_returns_at_once` failed once in a mutant run and passed on re-run.
- **No scanner.** CI runs no secret, dependency or static-analysis scanner, so that part is unmeasured. The diff changes no dependencies or workflows.
