All three guards are in, and draft PR #11 is open on branch `fix/path-guards`. Its head is `06ce5218a734e4f0e118824d2a22be9cd281b136`. I haven't read CI yet, and the gates have not run.

**What changed**
- **Session ids:** `hooks.session_id` is now the one check, where the hook input is read. An id that is not a string matching `[A-Za-z0-9_-]+` raises `hooks.Refused`. A missing id still becomes `unknown`. `cli.main` prints one stderr line and records only the error type in relay.log, which is inside the home.
- **Foreign home:** `private.home` now raises `PermissionError` when the home's owner is not the current user. Before, it went on and used that home without tightening it. `cli.main` runs this check through `wiring.home(cfg)` before any handler, so a refused home gets no writes, no journal line and no deletes.
- **Symlinked `listeners/`:** a new `private.remove` deletes through a folder handle opened with `O_DIRECTORY | O_NOFOLLOW`. `Listeners.clear` uses it, so a symlinked `listeners/` gives an error and nothing outside the home is deleted.

**Tests**
- **Red before the fix:** the 6 new tests in `PathGuardTest` gave 15 failures and 12 errors. Without the fix, quiet deleted `outside/s1.pid` through the symlink.
- **Green:** after merging origin/main (`86d57a1`, the release-please PR #9 and the 0.3.0 release #10), 91 tests pass on Python 3.14.5 and on /usr/bin/python3 3.9.6.
- **Mutants:** four, each run in a scratch copy, and all four failed the tests: dropping `O_NOFOLLOW` in `remove`, dropping the owner check, making the token check always pass, and dropping the `Refused` branch in `cli.main`.
- **Foreign-owner case:** the tests fake the uid by patching `Path.stat`, not `os.stat` as the brief said. Python 3.9's `pathlib` binds `os.stat` at import, so patching `os.stat` had no effect there and 8 tests failed on 3.9 only.
- **Sweep:** AUTH N.A. (no change to `signal_cli.py`), VAL, TEST, ERR, STATE and CON PASS, INF N.A. Details are in the PR body.

**Decisions recorded under Assumptions in the PR**
- An unsafe session id refuses the whole hook, permission and question included, even though there the id only reaches the journal.
- A root run against your home is now refused.
- A symlinked home pointing at another account's folder is now refused instead of used as is.
- `Listeners.get` still reads through a symlinked folder. Only deletion was in the promise, and `processes.stop` only kills a live relay.py.
